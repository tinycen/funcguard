## 审查并重写 tests/test_print_progress.py（funcguard 包）

### 原测试文件的问题
1. **f-string 表达式内带反斜杠**（原第 98 行 `{result.stdout.count("\\r")}`）：
   仅 Python 3.12+（PEP 701）合法。本项目 `python_requires='>=3.10'` 且 CI 覆盖 3.10/3.11，
   会直接 SyntaxError 导致整个文件导入失败。已改为先取 `cr = "\r"` 变量。
2. **flush 测试是假通过**：`capture_output` 在进程退出时总能拿到完整输出，
   实测去掉 `flush=True` 后仍能捕获到 `'X0X1X2'`，所以 `stdout.strip() != ""` 证明不了 flush。
   且 `range(5)` 配 `total=4` 只出 0/25/50/75/100%，`"80%"` 分支永不命中。
3. **raw 分支硬编码 utf-8 解码**：非 UTF-8 locale（中文 Windows 默认 GBK）下会解码失败。
   已统一给子进程注入 `PYTHONIOENCODING=utf-8`。
4. 缺少真实 `.py` 脚本文件场景（原来全是 `-c` 内联代码）。

### 新增能力
- `_temp_script()`：把源码写成真实 .py 临时脚本（contextmanager 自动清理）。
- `_run_script_file()`：subprocess 执行真实 .py 文件。
- `_stream_script_file()`：`Popen(bufsize=0)` 逐字节读，记录每个 `\r` 帧的到达时刻。

### 关键经验（验证 flush 的正确姿势）
- 用"**首字节到达时子进程是否存活**"判定有竞态：子进程退出瞬间刷数据，
  父进程 `poll()` 时它可能还没完全退出，会误判为实时（实测变异后仍通过）。
- 正确做法是测**帧到达时间跨度**（spread）。实测（Windows / Py3.13，5 帧 × 0.4s）：
  有 flush 跨度 ≈1.6s；无 flush 跨度 ≈0.001s。变异测试可稳定复现失败。
- `subprocess.run(text=True)` 会做通用换行转换，把 `\r` 转成 `\n`；
  要验证回车符必须走二进制流 + `io.TextIOWrapper(newline="")`。

### 发现 printer.py 的既有 Bug（未修，待用户确认）
`print_progress(15, 10)` → percent=150 → `'█'*(150//2) + '-'*(50-75)`，
`'-'*负数` 得空串，进度条实际长度变成 75 字符（超出设计的 50）。
另外 `\r` 只覆盖不清行，进度回退或 message 变短时会残留上一帧字符。
第三个：不感知 isatty，非终端环境（CI/日志重定向）会把日志刷爆。

## 实测数字（供复用，Windows / Py3.13，解释器启动开销约 0.6s）
- 5 帧 × sleep(0.4)：有 flush 首字节 0.670s，无 flush 2.705s；帧跨度 1.6s vs 0.001s
- 5 帧 × sleep(0.3)：有 flush 首字节 0.610s，无 flush 2.164s
- 11 帧进度：`text=True` 得到 0 个 `\r` / 11 个 `\n` / 12 行（开头多一个空行）；
  二进制得到 11 个 `\r` / 0 个 `\n` / 1 行
- `PYTHONIOENCODING=gbk` 时 `█` 编码为 `b'\xa8\x80'`（GBK 收录 U+2588，不报错但
  父进程按 UTF-8 解码会炸，属静默风险）

## time_utils / log_utils 彩色日志在 subprocess 中的行为（第 4 轮）
产出 `docs/time_log_subprocess.md`。核心结论：
1. `ColoredFormatter` **无条件**注入 ANSI（无 isatty / NO_COLOR 判断），
   捕获到的是 `'\x1b[31m02:18:20 消息\x1b[0m'`。这是控制字符污染，不是 mojibake。
   ESC 在任何编码都可表示，颜色码本身从不引发编码错误。
2. **logger stream 在 import 时绑定**（time_utils.py:10 模块级 setup_logger →
   StreamHandler(stream or sys.stdout)）。实测 redirect_stdout 只捕获到 print 路径，
   logger 那条漏到真实 stdout。pytest capsys 同理。
3. **编码失败静默丢失**：logger 路径 cp1252+中文 → rc=0、stdout 空、
   stderr 只打 `--- Logging error ---`；对照 print 路径 rc=1 硬抛。最难查的一类故障。
4. 父进程解码失败（子 GBK / 父 utf-8）：UnicodeDecodeError 发生在 subprocess 的
   `_readerthread`，**不传播到主线程**，`result.stdout` 变成 None。
5. `propagate=True` 未关闭 → 用户调过 basicConfig 时，同一条日志 stdout 彩色一份
   + stderr 纯文本一份。
6. `time_wait` 与 `print_progress` 同样的 `\r` 问题（3s 倒计时 → text=True 下 4 行）。

## 复用技巧：绕开 funcguard/__init__.py 的第三方依赖
环境未装 requests/curl_cffi/pandas 时，用 importlib 直接加载真实子模块：
构造 `types.ModuleType("funcguard")` 并设 `__path__`，再用
`spec_from_file_location("funcguard.time_utils", ...)` 逐个加载。
（单纯给 sys.modules 打桩不够 —— tools.py 在注解里用 `requests.Response`，
pd_utils 要 `pandas.api.types`，桩要能响应任意属性。）
